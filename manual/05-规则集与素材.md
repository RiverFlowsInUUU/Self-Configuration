## 5.1 一条总纲：清单两侧共用

两个内核引用**同一批**规则集（URL 相同、格式同为 Surge `.list` 方言）。这带来一个直接好处与一个直接义务：

- 好处：规则集在任一侧被审计脚本下载核对过，结论对另一侧同样成立；
- 义务：**改了任一侧的规则集引用（增删、换源、换 URL），另一侧必须同步评估** —— 同步清单见 [09 章](09-跨内核移植.md)。

各版"此刻引用了哪些、各多少条"不写在任何文档里，以 profile 文件本身与两侧 `docs/08` 读数为准。

## 5.2 承重结构：谁是主承重墙

国内域名直连的**主承重**是 Loyalsoldier 的 `direct.txt`（十一万级**纯域名**条目、零 IP）。围绕它有三条判据：

1. **它不需要也不能靠 `no-resolve` 说话** —— 纯域名规则集只做字符串匹配，任何情况不触发解析；"已是 IP 的连接"由 `GEOIP,CN / geoip: CN`（带 `no-resolve`）那条兜住。两条合起来才是"国内全覆盖"，**拆开任何一条都只交了一半**（[02 章 2.5](02-DNS原理与泄露面.md)）。
2. **`direct.txt` / CN 的 IP 判定 / 白名单 guard 不能删** —— 想精简配置的人请先读 [06 章精简指引](06-日常维护.md)。
3. **`.cn` 后缀兜底**：Egern 分流版在 `direct.txt` 之后还钉了一条 `domain_suffix: cn`，理由是"不依赖规则集是否加载成功"；Surge 侧未带（`direct.txt` 本身含 `DOMAIN-SUFFIX,cn`）。这属于两侧刻意保留的差异之一，见 [09 章](09-跨内核移植.md)。

## 5.3 挑规则集的判据：数条目，不看名字

规则集的名字与 README 标题**都不可信**，唯一判据是下载后数类型分布：

```bash
python skill/scripts/egern/profile_ruleset.py ChinaMax.list     # 或 weigh_ruleset.py
# 手工核（注意 GitHub raw 有 301，必须 -L）：
curl -sL <规则集URL> | grep -c '^DOMAIN'
curl -sL <规则集URL> | grep -c '^IP-CIDR'
```

历史案例（记住这个形状就够了）：`ChinaMax.list` 听起来最像"中国域名全量"，实测域名只有几十条、IP 占 99.5% —— 单用它承接"域名直连"，等于没有兜底。

同理，**远程规则集里可能藏着会触发解析的裸 IP 条目**（`Apple_All.list` 曾有 13 条，改用 `Apple_All_No_Resolve.list` 解决）。这类问题不在你的 profile 里，本地静态审计看不见 —— 所以引入规则集前跑一次：

```bash
python skill/scripts/egern/audit_ruleset_noresolve.py <profile>   # Egern 侧，联网
python skill/scripts/surge/audit_ruleset_content.py <profile>     # Surge 侧，联网
```

## 5.4 URL 与刷新参数的规矩

| 规矩 | 原因 |
|:-----|:-----|
| 规则集 `update-interval`（Surge）/ `update_interval`（Egern）显式钉成同一周期（现值见 profile） | 不写 = 把刷新行为交给未知默认值；两侧同一写法是刻意的。**每条规则集各自带**，别只写第一条 |
| `AI.list` 的 URL **钉到 commit 号** | 上游 master 会漂移，AI 域名清单一动分流就变 |
| 去广告清单用 **RULE-SET 版**地址（`…-Surge-RULE-SET.list`） | 同仓库的另一个同名文件是**裸域名**（`DOMAIN-SET` 格式），与 `rule_set` 不匹配，**勿混用**；RULE-SET 版条目更全 |
| 白名单 guard 排全部规则**最前**，广告拦截排其后 | 顺序铁律，见 [03 章 3.4](03-Surge操作.md) |
| 图标只引用本仓 `icons/`（`raw.githubusercontent.com/RiverFlowsInUUU/Self-Configuration/main/icons/…`） | 不依赖外部图标源；绝对 URL 让 iOS 导入也不破图。路径必须**纯 ASCII**（客户端读取的坑），来源与许可见 [11 章](11-许可与图标.md) |

## 5.5 引入 / 更换规则集的标准动作

1. 下载数类型分布（5.3）；
2. 确认它与"成对交付"两条判据不冲突（动了直连侧就重跑分流覆盖审计）；
3. 两侧同步评估（5.1）；
4. 刷新参数按 5.4 的表补齐；
5. `audit_ruleset_refresh.py`（两侧各一份）+ 对应内容审计脚本全过；
6. CHANGELOG 记一笔。
