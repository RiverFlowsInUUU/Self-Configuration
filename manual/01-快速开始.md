# 01 · 快速开始

> 目标：从零到「装好、能通、确认没泄露」，全程只改你需要改的地方。
> 想先懂原理再动手的，跳 [02-DNS原理与泄露面](02-DNS原理与泄露面.md)。

---

## 第 0 步 · 两个决定

### 决定一：选内核

| | Surge | Egern |
|:--|:------|:------|
| 平台 | iOS / macOS / tvOS / visionOS | 仅 Apple 平台（iOS 为主） |
| 配置格式 | INI（`.conf`，分节 `[General] [Proxy] [Proxy Group] [Rule]`） | YAML（`.yaml`，顶层 `dns:` / `proxies:` / `policy_groups:` / `rules:`） |
| 仓库文件 | [`../surge/profiles/`](../surge/profiles/) | [`../egern/profiles/`](../egern/profiles/) |

两个内核的配置**互不兼容、不要混用**。已有哪个客户端就用哪侧。

### 决定二：选分工（二选一，不要叠加）

| | 懒人版 `lazy` | 分流版 `routing` |
|:--|:-------------|:-----------------|
| 定位 | 只想通、不想调 | 想让 ChatGPT 走美国、Claude 走台湾、微信直连 |
| 出口粒度 | `Proxy` / `AI` / `AD` 三路 | 按**应用**分组，组内再按**地区**分 |
| 防泄露标准 | **两份完全一致**（DNS 相关键被测试断言为逐字相同） | 同左 |

> ⚠️ 它们是**分工关系，不是版本关系** —— 一份导入即可，同时开两份没有意义。
> 防泄露结构两份共享，分流粒度不同而已。

## 第 1 步 · 拿到文件

每个内核、每份分工都有**两种形态**：

| 形态 | 文件名 | 用途 |
|:-----|:-------|:-----|
| 带注释完整版 | `lazy.conf` / `routing.conf`（Egern 为 `.yaml`） | 读、改 |
| 纯配置 `.min` 版 | `lazy.min.conf` / `routing.min.conf`（同上 `.min.yaml`） | **导入用这个** |

同名两份内容一致、只差注释（由测试逐字节核对）。导入 `.min` 版后想再理解某个键，回到完整版或 `DetailsReadme` 查。

**固定订阅地址**（永久有效，不随版本号变化）：

```
https://raw.githubusercontent.com/RiverFlowsInUUU/Self-Configuration/main/surge/profiles/lazy.min.conf
https://raw.githubusercontent.com/RiverFlowsInUUU/Self-Configuration/main/surge/profiles/routing.min.conf
https://raw.githubusercontent.com/RiverFlowsInUUU/Self-Configuration/main/egern/profiles/lazy.min.yaml
https://raw.githubusercontent.com/RiverFlowsInUUU/Self-Configuration/main/egern/profiles/routing.min.yaml
```

> 📌 「当前是哪一版」只写在 profile 头部注释 `#! version=...` 里，**文件名永远是这四个固定名** —— 订阅地址因此不会失效。

**iOS 注意**：Surge / Egern 的 iOS 版对本地文件支持有限（Surge iOS 需要 URL 导入）。用上面的订阅地址直接导入是最省事的路径；自己改过的配置托管到自己的仓库 / Gist 再用 URL 导入。

## 第 2 步 · 替换必须由你填的部分

模板刻意**不含任何真实节点**。导入后必须替换：

| 内核 | 版本 | 必须动哪里 |
|:-----|:-----|:-----------|
| Surge | `lazy` | `[Proxy]` 段的占位节点 —— 换成你自己的节点，或整段删掉改走订阅 |
| Surge | `routing` | `Airport` 组的 `policy-path=<你的订阅 URL>` 占位符 —— 填机场订阅地址即可，地区组会自动从订阅节点里筛 |
| Egern | 两版 | `proxies:` 为空 —— 在客户端里添加自己的代理，或把 `policy_groups` 里 `external` 型策略组的 `url` 换成你的订阅地址（这是模板说明里标注的「必须替换 1 处」） |

> ⚠️ 节点名里要带地区关键词（`🇭🇰` / `香港` / `HK` 等），分流版的地区组靠**正则筛节点名**，名字里没有关键词的组会是空组。
> ⚠️ **绝不把真实节点 / 订阅地址提交回本仓库** —— 这是仓库红线，有测试拦。

## 第 3 步 · 五分钟自检

装完先跑这四条，全过才算装对：

1. **DNS 泄露测试**：浏览器打开任意 leak test 网站。
   - 结果里**不应出现运营商 DNS 服务器 / 国内运营商出口 IP**；
   - ⚠️ 显示**节点出口城市的 IP 不是泄露** —— 那正是代理在工作的证据，别去"修"它。
2. **国内直连**：打开 `qq.com` 或 `jd.com`，客户端连接日志里策略应为 `DIRECT`（不是走代理绕出境）。
3. **境外走代理**：打开 `google.com`，应走 `Proxy`（Egern 走 `Final → Proxy`）。
4. **脚本审计**（可选，改了配置的人必跑）：

```bash
# Surge 侧（离线、秒级）
python skill/scripts/surge/check_surge_dns.py surge/profiles/lazy.conf
python skill/scripts/surge/check_surge_dns.py surge/profiles/routing.conf

# Egern 侧
python skill/scripts/egern/check_egern_dns.py egern/profiles/routing.yaml
```

期望退出码 `0`。脚本怎么用、退出码含义、联网审计见 [08-验证与自检](08-验证与自检.md)。
