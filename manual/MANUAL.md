# 《Self-Configuration》操作手册

本手册是仓库唯一的权威操作文档，2026-09-25 由散在 `docs/`、`surge/docs/`、`egern/docs/` 的数十篇讲解文档自底向上整合而成。
旧文档已就地冻结（顶部有横幅），每篇内容的去向见 [99-版本历史](99-版本历史.md) 的映射表。

---

## 手册的定位

讲「怎么装、怎么改、怎么验、怎么修」。从任何一篇旧文档带来的问题，都应能在这里、或它指向的活文档得到答案。

三件事它刻意不抢：

| 它不是 | 谁是这个 |
|:-------|:---------|
| 仓库门面 | [根 README](../README.md)：「📖 按需查阅」及以上保持原样，以下与本手册同步 |
| 逐键参考书 | 两份逐键附录 —— [Surge DetailsReadme](../surge/DetailsReadme/DetailsReadme.md) · [Egern DetailsReadme](../egern/DetailsReadme/DetailsReadme.md)。每个配置项的完整语义与出处仍以它们为准，本手册只讲操作 |
| 读数报表 | 审计读数只落在 [surge/docs/08](../surge/docs/08-审计读数.md) · [egern/docs/08](../egern/docs/08-审计读数.md)。本手册不写死任何读数 —— 组数、规则数、断言数、规则集条数一律不抄。这是本仓的纪律：期望值从源头现算，文档不复述会漂的数字 |

## 三层地图：docs · skill · manual 各是什么

仓库的 markdown 按职责分三层，它们是分工不是三代文档：

| 层 | 位置 | 放什么 | 给谁读 |
|:---|:-----|:-------|:-------|
| 入口层 | 本 `manual/` | 操作性知识：怎么装、怎么改、怎么验、怎么修 —— 全部接管在这里 | 人 |
| 附录层 | `docs/` · 两侧 `surge/docs` / `egern/docs` · 两侧 `DetailsReadme` | 三类权威原件：清单（规则集与来源 / 跨内核差异对照 / 注意事项）· 读数报表（两侧 `docs/08`）· 逐键语义与历史（`DetailsReadme`、`docs/07`、已冻结专题文档） | 人，按需查 |
| 工具层 | `skill/` | 审计脚本、回归闸门、判据及其演进史（`SKILL.md` / `scripts` / `tests` / `reference`） | agent 与维护者 |

> **注意**　三个目录合并成一个不可行，且已被逐文件核过：`check_doc_readings.py`（冻结闸门文件）的 LIVE 清单按路径钉死附录层多个文件；`CHANGELOG` / `体检报告` / `日志旧版原文` / `public-repo.md` 含几十处指向这些路径的历史链接；`skill/` 内部全是相对路径自引用。动任何一层都会撞上其中之一。合并发生在内容层 —— 操作性知识已全部进本手册，另两层只保留"只能存在于那里"的东西。

往后什么写去哪，按这张表分流：

- 新的操作性知识 → 手册对应章节；不再往已冻结文档追加，也不新开专题篇；
- 新规则集、图标、跨内核差异 → `docs/` 的权威清单本体（手册只写判据与指向）；
- 会随配置漂的读数 → 只落两侧 `docs/08`，手册与 README 都不抄数；
- 新判据、事故复盘 → `skill/reference/`（`checker.md` / `pitfalls.md`）；若影响使用者视角，手册同步一条操作指引。

## 项目一句话

面向 Apple 平台的两款代理客户端 Surge 与 Egern，提供防 DNS 泄露的开箱即用配置模板：
两份分工（懒人版 `lazy` / 分流版 `routing`）× 两种形态（带注释完整版 / 纯配置 `.min` 版）× 两个内核，
配一整套本地审计脚本与回归闸门。

核心命题只有一条：**「DNS 不泄露」和「分流正确」是同一个机制的正面和反面，必须成对交付。**

## 手册自身的维护规则

1. 新的操作性知识写进本手册，不再往已冻结的旧文档里追加。
2. 本手册不写死读数（见「定位」表第三行）；需要引用读数时，链接到两侧 `docs/08`。
3. 修改本手册同样要过闸门：`bash skill/tests/all.sh` 的链接检查会扫全仓 markdown，断链即红。
4. 每次实质性更新在 [CHANGELOG](../CHANGELOG.md) 记一笔，体例见其文首。
