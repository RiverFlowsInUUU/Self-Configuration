## 归档策略：就地冻结，未做物理搬迁（以及为什么）

原计划将部分旧文档 `git mv` 进 `docs/_archive/legacy-2026-09-25/`。逐文件核过闸门与链接后，结论是**任何物理搬迁都会撞上一条更高优先级约束**，因此全部改为**就地冻结**：顶部横幅 + 本表映射 + 手册接管。实测依据三条：

1. **读数判据锁路径**：`skill/tests/check_doc_readings.py`（冻结闸门文件，不许为搬迁而改）的 LIVE 清单钉死了
   `docs/注意事项.md`、`docs/规则集与来源.md`、`docs/跨内核差异对照.md`、`surge/docs/11-分流版设计.md`、两侧 `docs/08`、两份 `DetailsReadme` 的**原路径** —— 移走即"命中 0 处 ⇒ 判负"的假红。
2. **历史链接锁路径**：`CHANGELOG.md`（只可追加的历史记录）、`docs/体检报告.md`、`docs/日志旧版原文.md`、
   `skill/reference/*/public-repo.md` 内含指向各专题旧文档的链接，而 `check_links.py` 全树扫链接 —— 搬迁要么改这些不该改的文件，要么闸门红。
3. **根 README 锁目录形态**：整合时门面为「不可修改」，且描述了"各内核 `docs/` 下一套编号专题文档"的结构。
   （同日维护者授权改版其下半 —— 「📁 文件结构」起已指向本手册；上半仍原样，就地冻结的决定不受影响，依据是第 1、2 条。）

`docs/_archive/legacy-2026-09-25/` 仍建立，其 [`README`](../docs/_archive/legacy-2026-09-25/README.md) 记录该决定与完整名单。

4. 每次手册实质更新：CHANGELOG 一条（改了什么 · 哪里没动 · 验收）+ `bash skill/tests/all.sh` 绿。
