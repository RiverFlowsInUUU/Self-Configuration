# 跨内核差异对照

> 本仓库把 Surge 与 Egern 两套模板合到一处。**分组与规则已基本对齐**，但两款内核实现逻辑不同。
> 这一页是给"想把一侧的改动移植到另一侧"的人看的：哪些能直接照搬、哪些照搬就是错的。
> 结论均来自对 `surge/profiles/routing.conf` 与 `egern/profiles/routing.yaml` 的逐条比对。

---

## 1 · 语法映射

| 语义 | Surge | Egern | 移植时注意 |
|:-----|:------|:------|:-----------|
| 配置载体 | `.conf` INI 分段 | `.yaml` | — |
| 本地 DNS | `dns-server = a, b` | `dns.bootstrap` / `dns.upstreams` | Egern 分「默认 DNS / 代理 DNS」两条路，Surge 只有一条 |
| 加密 DNS | `encrypted-dns-server = https://…` | `dns.upstreams.<组名>` | 判据是写 **IP 字面量**；Surge 侧对 2 条主机名端点挂了显式豁免，见第 8 节 |
| 代理侧解析 | 无独立键（由 `dns-server` 承担） | `dns.proxy_nameservers` | ⚠️ Egern 一旦设它就**跳过 `forward`**，Surge 无此机制 |
| 接管明文 53 | `hijack-dns = 8.8.8.8:53, …` | `hijack_dns: ['*']` | Egern 支持通配全接管；Surge 侧只能列清单，判据是"还漏几个知名解析器" |
| 不解析 | `no-resolve`（规则行内） | `no_resolve: true`（规则字段） | ⚠️ Egern 仅对 `geoip`/`ip_cidr`/`ip_cidr6`/`asn` 四类生效，写在 `rule_set` 上不生效 |
| 远程规则集 | `RULE-SET,<URL>,<策略>` | `- rule_set: {match, policy}` | 两侧都可直接引用 Surge 格式 `.list` |
| 刷新间隔 | `"update-interval=604800"` | `update_interval: 604800` | 本仓**两侧统一一周、且都显式写死**。理由不同：Surge 缺省就是 86400（只有写负值才关自动更新），显式写是为了可见；Egern 未文档化缺省值，不写就是行为不可知 |
| 策略组 | `[Proxy Group]` | `policy_groups:` | 见下节，两组 26 项已对齐 |
| 组展开 | `include-other-group="X"` | `flatten: true` | 语义等价（复制的是 resolved member policies） |
| 组内正则筛选 | `policy-regex-filter` | `filter` | ⚠️ Surge 的 `policy-regex-filter` **对显式列出的成员无效**，需同时 `include-all-proxies=true` |
| 地理判定 | `GEOIP,CN,DIRECT,no-resolve` | `- geoip: {match: CN, …, no_resolve: true}` | — |
| 默认出口 | `FINAL,<组>,dns-failed` | `- default: {policy: <组>}` | Surge 可带 `dns-failed`；Egern 无此参数 |
| 解析阶段拒答 | `REJECT,pre-matching,extended-matching` | `dns.forward` 里 `value: reject` | ⚠️ 机制完全不同但**目的相同**：都在解析阶段掐断，不产生后续查询 |
| 内置 LAN | `RULE-SET,LAN` | 无内置 → 引用 `Lan.list` | 实测差异之一，见第 3 节 |
| 内置系统进程 | `RULE-SET,SYSTEM` | 引用本仓快照 `apple_system.list`（= 内置集的时点内容，缺两条 `PROCESS-NAME`） | 2026-09-24 起两侧同位各一套；Egern 侧没有进程名匹配能力，那两条接不住 |

## 2 · 分组：已完全对齐

`routing_v3.2` 两侧各 **26 个分组，名称与顺序逐位相同**（实测逐行 diff 无差异）：

```
Proxy · Smart · ChatGPT · Gemini · Claude · AI · Spotify · YouTubeMusic · YouTube
GitHub · Google · Microsoft · Telegram · Twitter · Airport · WeChat · AD
Hong Kong · USA · Japan · Taiwan · Singapore · Korea · Other Regions · MAX · Final
```

移植分组改动时唯一要换的是写法：Surge 用 `include-other-group` + `policy-regex-filter`，
Egern 用 `policies` + `flatten` + `filter`。地区组倍率筛选的正则两侧共用同一份
（`(?<![\d.])0\.\d*[1-9]` 收所有倍率 < 1 的节点）。

## 3 · 规则：24 条位位对应，三处引擎差异

顺序两侧一致（白名单 → 广告 → 内网 → 应用组 → 国内兜底 → 地理 → 默认）。三处**不是疏漏、而是内核能力差异**：

| 位 | Surge | Egern | 性质 |
|:-:|:------|:------|:-----|
| ④ | `RULE-SET,LAN`（内置） | `Lan.list`（blackmatrix7） | 内置规则集的有无 |
| ⑲ | `RULE-SET,SYSTEM`（内置）→ `DIRECT` | `apple_system.list`（**本仓自托管**快照）→ `DIRECT` | 同一套系统域名规则的两种载体。快照删了 Egern 不支持的两条 `PROCESS-NAME`（`trustd` / `netbiosd`）⇒ Surge Mac 上那两条还额外接住两个系统进程的请求，Egern 侧接不住。两侧都不再占位给 `Proxy.list`（它已改成注释态，两边同写法） |
| ②③ | 两条广告清单 → `REJECT`（字面量） | 两条 → `AD`（策略组） | ⚠️ **方向相反**：Surge 侧 `pre-matching` 的规则**策略必须是字面量 REJECT 族**，写成策略组会导致 Surge **拒绝加载整份配置**；Egern 无此限制，故用 `AD` 组以便面板上开关 |

> 移植提醒：把 Egern 的"广告指向 `AD` 组"照搬到 Surge 的 `pre-matching` 规则上，
> 后果不是效果差一点，而是**整份配置加载失败**。
>
> 📏 **禁用一条规则也只能各自按内核的写法来**：Surge 的 `RULE-SET` 只认 `no-resolve` /
> `extended-matching` / `update-interval` / `pre-matching` 四个参数，**没有 disabled 字段**，
> 不想要的行只能注释掉；Egern 有 `disabled: true`，但它**仍占 `rules` 数组的一位** ⇒
> 想保持逐位对齐就得两边都用注释。本仓 `Proxy.list` 即按此统一（2026-09-24）。
>
> 🧪 **规则级 `no-resolve` 的同一条原则，两内核落点不同**：原则是「实测零 IP 条目的规则集不写，
> 真含 IP 的必须写」。Surge 写在规则行末尾；Egern 的 `no_resolve` 只适用 `geoip`/`ip_cidr`/
> `ip_cidr6`/`asn`，**写在 `rule_set` 上不生效** ⇒ 它的同层防线落在规则集文件里（条目级
> `,no-resolve`），由 `audit_ruleset_noresolve.py` 逐个下载核对。

## 4 · 懒人版：对齐程度明显低于分流版

`lazy` 两侧**并未逐条对齐**，这是现状而非缺陷，移植时务必按实际来：

| | Surge `lazy.conf` | Egern `lazy.yaml` |
|:--|:-----------------|:-------------------|
| 规则条数 | 10 | 10 |
| 广告拦在哪一层 | `pre-matching` + `extended-matching` → **DNS 与 TCP-SYN 阶段** | `dns.forward` 两条 `value: reject` → 同样在**解析阶段**拒答（2026-09-23 补齐） |
| 系统域名集 | ✅ 内置 `SYSTEM` | ✅ 本仓快照 `apple_system.list`（缺两条 `PROCESS-NAME`） |
| Apple 全量规则集 | ❌ 无（2026-09-24 删，只留内置 `SYSTEM`） | ❌ 无（Apple 流量部分由 `direct.txt` 兜住，`iCloud` 系走节点） |
| 内网两条 | ✅ `LAN`（内置）+ `private.txt` | ✅ `Lan.list` + `Private`（2026-09-23 补，与分流版同源同策略） |
| `.cn` 后缀兜底 | ❌ 无 | ❌ 无（2026-09-24 删：`direct.txt` 本身含 `DOMAIN-SUFFIX,cn`） |
| 内网规则位置 | 排在 `AI` 之前（2026-09-24 与 Egern 拉平） | `Lan` / `Private` 排在 `AI` 之前 |
| 默认出口 | `FINAL,Proxy,dns-failed` | `default` 规则 `policy: Proxy`（两侧都无 `Final` 中间组，2026-09-23 拉平） |
| 分组数 | 3 | 3 |

分流版做过逐行对齐，**懒人版历史上没有** —— 2026-09-23 补齐三项（`dns.forward` 四层、`Private` 规则集、
`AI` 组的 `flatten: true`）并把 Egern 的兜底组 `Final` 整块移除（`default.policy` 直写 `Proxy`）；
**2026-09-24 补齐最后两处**：Surge 侧删 Apple 全量集并把内网段提前（两侧同为 10 条、同一顺序），
Egern 侧删 `domain_suffix: cn` 并补上系统域名集。
⇒ 现在改一侧懒人版**可以**假设另一侧同构，但改动仍要两边各写一次：同构指「位数与语义」，不指「字节」。

## 5 · 版本保留策略：两侧刻意相反

- **两侧同一套（2026-09-24 起）**：`profiles/` 顶层只有固定名四件 —— `routing` 分流版 + `lazy` 懒人版，各含带注释版与 `.min` 版；订阅地址就是这个永久文件名，升版不改名。
- **被替代的进 `profiles/config_old/`**：按「小数点后一位」的进位规则命名（`v3.2` 之后是 `v3.3`，`v3.9` 之后是 `v4.0`）。Surge 侧现有 `routing_v3` / `v3.1` 两版 + `lazy_v1.0` 快照；Egern 侧保留 `routing_v1 → v3.1` 全部 8 版，供逐版对照。归档不参与检查。

理由是 Egern 侧的谱系本身是方法论文档的一部分（每版头部写明"为什么改"），而 Surge 侧是在其之后建立、
直接继承结论。**合并版沿用两侧原状**，未强行统一——要统一需要先决定舍弃哪一侧的历史。

## 8 · 保持原样的差异与源仓遗留问题

1. **加固清单项数不同**（Surge 14 项 / Egern 18 项）。两侧各有对方的判据没有覆盖到的面，
   合并成一张带内核列的总表需要逐条判定"是同一件事的两种表述"还是"确实内核独有"，
   目前**保持各自原状**，见 `surge/docs/03-加固清单-14项.md` 与 `egern/docs/03-加固清单-18项.md`。
2. **同一判据、两处不同取舍：加密 DNS 端点的写法。**
   Surge 侧 `encrypted-dns-server` 三条端点里有 2 条写的是**主机名**
   （`https://dns.google/dns-query` / `https://dns.alidns.com/dns-query`），会被引导解析一次；
   Egern 侧 `upstreams` 四条端点**全部 IP 字面量**，无引导解析。
   这**不是 Surge 侧的疏漏**：两侧模板头部各写明判据，Surge 侧在 profile 里显式挂了豁免
   （`# audit-waive: 1 加密 DNS 端点保留 2 个主机名形式`），换来的是 CDN 就近解析与 ECS 合规两项收益。
   移植时不应把"全 IP 字面量"当作硬指标 —— 先确认自己要不要那两项收益。
   > 审计器的豁免只把 finding 降级成 `WAIVED:` 并照常打印，不改判据本身；判据写在 profile 里，可 grep、可复核。
3. **源仓文档中的五处过时内容**（合并版已修，源仓未改动）：
   - Surge `docs/11-分流版设计.md` 的懒人版对比块仍列着已删除的 3 条游戏机域名规则
     （合并版已改为按现状表述：两侧 profile 都只有 `always-real-ip` 里的这些主机名，
     `[Rule]` 段没有对应规则）；
   - Egern `docs/11` 第 84–101 行是一段编辑残留的孤立表格碎片；
   - Egern 有 **3 条**指向**已撤下的 README 章节**的失效锚点（`#-两份配置` / `#-分流版`），
     分别在 `CHANGELOG.md` 头部、`DetailsReadme.md` 与 `docs/09-注意事项.md`
     —— GitHub 对失效锚点**不报错**，点了就是回到页面顶部。合并版逐条改指实际存在的章节。
   前两处是在**重建**那两篇共享文档时发现并直接修掉的；后三处由锚点检查器抓出
   （对照测试：Surge 源仓 28 个锚点全通过，Egern 源仓 21 个中仅这 3 条失效）。
4. **对两侧分支正文的三类刻意修订**（合并层，源仓未改）：
   - 标题降级与路径改写 —— 合并时就做过，属「逐字保留」承诺里写明的那一类；
   - **失效外链修复**（2026-09-23）—— Surge 手册把旧的 `/policy/*.html` 一层拆成
     `/dns/`、`/rules/`、`/policy-groups/`、`/policies/` 四个章节，`skill/SKILL.md` 分支 A 的
     四条引用链接因此全部 404，现逐条改指新章节（八条链接实测 200）；社区参考实现
     `repcz.github.io/Egern` 迁至 `doc.repcz.link/egern/`，分支 B 与 `egern/docs/01` 两处一并改指。
   - **去掉两份内嵌的假 YAML 头**（2026-09-23）—— 合并产物里，分支 A 与分支 B 的开头各压着一段
     源技能包的整段头部（`name` / `description` / `agent_created`，共 12 行）。**根因不在源仓**：
     源文件各只有一份头部、位置正确；是装配脚本剥头部的正则按 LF 写，而 Windows 上
     `core.autocrlf=true` 把工作区 checkout 成 CRLF，正则匹配不上 → 头部整段漏进正文。
     现已让装配脚本先归一化换行（从干净克隆重跑即得干净的树），并把两份头部里尚未覆盖的检索线索
     并进文件头那一条 `description`。**只删装配事故，不动正文一字**。
   三类都**不改变论述与判据**：前两类只按行改 URL，第三类删的是本就不该出现在正文里的行；
   分支正文的**全部代码块仍与源文件字节一致**（4 段逐字复核），依据都可复核。
5. **规则集刷新参数：一处事实更正 + 两份新判据**（2026-09-23，合并层新增，源仓未改）。
   这是本仓**第一次改动一条 substantive 论述**（前四类都只是修链接 / 删装配事故 / 改指向），所以单独列一条：
   - **更正**：原表述「不显式写 `update-interval`，规则集就会停在首次下载的版本」**因果是错的**。
     Surge 手册对 `RULE-SET` 写明 `Default: 86400 (24 hours)`、**负值才关闭自动更新** ⇒ 漏写只是周期不可见；
     真正**未文档化缺省值**的是 Egern 侧（官方 `rules` 页只在示例里出现 `update_interval: 86400`，
     字段节只写 `no_resolve`）。据此改写了 7 处会把这个错误因果继续传给后来人的文本
     （`docs/注意事项` / `docs/规则集与来源` / 本篇 §1、`hardening-template` §4.6、两侧 `docs/04`·`07`·`DetailsReadme`）。
   - **新增两份同名脚本** `audit_ruleset_refresh.py`（Surge / Egern 各一份）：判据相同、**依据不同**，
     正是「同一件事的两种内核表述」需要各自成文的那种 —— 不并入两侧既有审计器的编号，
     避免把 Surge 的 14 项 / Egern 的 18 项清单改掉（§8 第 1 条的项数差异保持原样）。
   - **判据分档**：非正值 = HIGH（唯一会真的停在旧版的写法）；缺字段或偏离约定值 = 「约定」档，
     默认不影响退出码（历史版本按当时口径交付），当前推荐版与懒人版由回归以 `--strict` 守住。
   - **字节差异范围随之扩大**（反解回源形态后逐字节相同的文件 **39 个**，其余 **52 个**需人工确认，
     含 4 份源仓里根本不存在的新版 v3.1 profile、两份新脚本，以及当时已进仓的三个本仓自写文件
     —— `skill/tests/all.sh` · `check_min_pair.py` · `bump_version.py`；第四个 `check_portability.py`
     进仓时这套对账已随「与前身仓逐字节比对」一起退役，**不再重算**，见第 7 条）。差异**只落在四类**：
     ① 刷新参数那一行；② 文档里的脚本数 / 断言数 / 读数；③ 订阅与命令示例的版本指向；
     ④ **输出编码垫片**（中文 Windows 默认 GBK，脚本 print emoji 会崩成退出码 1 ⇒ 判负 fixture 假绿，
     故 10 个 Python 文件（含两个 `_common`）+ 3 个 shell 入口各加了统一钉 UTF-8 的一行 / 一个环境变量）。
     这四类都是**环境正确性与数字口径**，不动任何判据逻辑与正文论述；
     本仓不声称「与源仓完全一致」，只承诺**分支正文的代码块逐字一致**（`skill/` 两侧正文逐段复核）。
6. **回归 runner 的三处内部重构**（2026-09-23 第二轮，合并层新增，源仓未改）。
   三个脚本本就在必改差异清单里（清单条目名未变，仍是当时那 49 项 / 逐字节相同 39 个），单独列一条是为了
   把第 5 条末尾那句「差异只落在四类」补全 —— 现在还多了第五类：**测试脚本自身的口径重构**。
   - **「当前推荐版」从十几处文件名收成一行常量** `CURRENT="${CURRENT:-routing_v3.2}"`
     （Surge 的 `run.sh` / `architecture.sh` 与 Egern 的 `run.sh` 各一行）。它仍是**承诺值**、
     刻意不推导「仓库里最大的版本号」，与 `architecture.sh` 的组顺序表 `PG_ORDER` 同一条纪律：
     升版必须有人显式改这一行，改动本身即是一次确认。
   - **配套前置检查**：`$CURRENT` 指向的 profile 不存在 ⇒ **退出码 2**。原先缺失文件会被
     `continue` 掉，整个阶段静默不跑、输出照样全绿 —— 与「GBK 下解释器崩成退出码 1」是同一类假绿。
   - **Egern 断言口径统一到「按脚本对账」**：阶段 1 的 5 行 fixture 每行校两个脚本 ⇒ 计 10 条，
     加阶段 2 的 18 × 2 = 36 ⇒ 46；runner 末尾新增合计 `TOTAL:` 行。此前它自己报 41、文档写 46。
   三处**只动测试脚本内部**，不碰任何判据逻辑与 profile 内容。
   - ⚠️ **该常量已于 2026-09-24 退役**：订阅地址固定化之后当前版恒为 `routing.*`，
     「哪一版」只剩 profile 头注 `#! version=routing_vX.Y` 一处显式承诺，
     形状与两侧一致性由 `skill/tests/check_min_pair.py` 判（口径见 §5 与根 `CHANGELOG.md` 当天段）。

7. **本地检查进仓，且只看本仓**（2026-09-23 第三轮，合并层新增）。
   - 进仓三件：`skill/tests/all.sh` 一条命令跑完**全部本地检查**（两内核回归 + 全仓链接与锚点
     + 两版形态去注释对拍，退出码 0 / 1 / 2）；`skill/tests/check_min_pair.py` 补的是此前无人守的
     空档 —— `architecture.sh` 的 ② 只比 DNS 键、④-b 只比组顺序，且**只管 Surge 侧**，
     Egern 的两版形态从没对拍过整份配置；`skill/tests/bump_version.py` 收走升版的机械部分。
   - ⚠️ **2026-09-24 补一句**：`.min` 的手工同步也已收走 —— `skill/tests/make_min.py` 直接 import
     `check_min_pair.py` 的那套判据函数重算正文（注释按锚点继承），**生成器与对拍器共用同一份规则**，
     不存在"生成器跑歪 yet 对拍放行"的空间；它不碰完整版，也不碰 `config_old/`。
   - 当时曾把「与前身仓逐字节对账」「前身仓是否被改动」两项留在仓外，理由是"一次性验收"。
     **这个理由不成立，已改**：本仓的立场是**完全独立** —— 只要有一项默认检查需要别的仓库在场，
     换一台机器就会爆红，那这项检查就不该存在。两个前身仓自本条起**不再构成本仓的任何前提**，

8. **换设备一致性：`.gitattributes` 钉死字节 + 可移植性检查进仓**（2026-09-23 第四轮，合并层新增）。
   这一条针对的是「clone → 直接改 → 推上去，双端一致」这个使用方式里**唯一还没被守住**的环节。
   - **病根是行尾，不是命名**：Windows 版 Git 安装器把 `core.autocrlf=true` 写进**系统级**配置，
     实测本机 `git config --system core.autocrlf` = `true`。效果是同一个 commit 在 Windows 上
     落盘 **88 个 CRLF 文本文件**、在 Linux / macOS 上落盘 LF。提交内 blob 一直是干净的
     （128 个跟踪文件里只有 26 个 png 含 CR 字节，那是二进制本征），坏的只是
     **「磁盘字节随设备变化」**这一件 —— 而它恰好让"线上线下逐字一致"无法在磁盘上验证，
     并且历史上真咬过一次：剥 YAML 头的正则按 LF 写，在 CRLF 工作区上失配，源技能包头部整段漏进正文。
   - **修法**：仓根新增 [`.gitattributes`](../.gitattributes)，`* text=auto eol=lf` + 二进制资产标 `binary`。
     `eol=lf` 优先级高于 `core.autocrlf` ⇒ 不需要任何人改本机配置。加完后 `git add --renormalize .`
     **索引零变化**（反证 blob 本就 LF），再把跟踪文件删净重新检出 ⇒ **128 / 128 个文件磁盘字节 = 提交字节**。
     本仓没有任何文件需要 CRLF（`.bat` / `.cmd` / `.ps1` 数量为 0），故取全 LF。
   - **命名实测**（128 条路径）：全部 NFC、无 Windows/macOS 非法字符、无保留设备名、
     大小写折叠零冲突、最长相对路径 **49 字符**、零字节文件 0 个、符号链接与 submodule 0 个、
     被跟踪的单机残留 0 个。中文文件名**不影响上传 GitHub**，本仓的纪律是：
     只出现在人读层 —— `docs/` · `*/docs/` · `manual/`（实测非 ASCII 跟踪路径 37 条：`manual/` 12 · `surge/docs/` 9 · `egern/docs/` 9 · `docs/` 7），机器消费的路径（`skill/` · `*/profiles/` · `icons/` · `*/scripts/` · `*/tests/`）纯 ASCII。
   - **固化成判据**：新增 `skill/tests/check_portability.py`（纯标准库），
     `all.sh` 从 3 项变 **4 项**；它报的是**固定 18 条规则**通过与否，**不随文件数增长**
     —— 与第 6 条「CURRENT 是承诺值」同一条纪律，免得升版时又要改文档里的数。
     反例已实测能判负：塞进一个 CRLF 文件 → E2 红；把中文命名放进 `skill/` → N6 红；
     改掉 `.gitattributes` 那一行 → E1 红（三种都 exit 1 并点名文件）。
   - `all.sh` 末尾新增一行**双端对账**：`未提交 N · 落后 N · 未推送 N`，三个数全 0 才算同步
     （这三个数自 2026-09-24 起由 `all.sh --landed` 判，默认档只报不判）；
     上游不存在时如实写「未配置」，不静默（clone 出来的仓天然有上游）。
   - Surge 19 / Egern 46 / 形态对拍 12 三项读数**不变**；本轮 profile 与判据逻辑零改动。
   - **复测把「88」这个数字问穿了**（同日补记）：88 是**当时磁盘上碰巧带 CR 的文件数**，不是机制上限 ——
     git 只改写检出时认为需要改写的文件。在修前的那个 commit 上**强制全量重检出**实测
     **101 / 101 个文本文件全 CRLF** ⇒ 病根比原记录更普遍；当前 `main` 的 fresh clone 则是
     **含 CR 0 个、磁盘字节 = 提交字节 105 / 105、`git status` 干净**。
   - **`E2` 的一处盲区已修**：`is_text()` 原来只认扩展名白名单 ⇒ `LICENSE` 这类无扩展名文本文件
     从未进过字节判据（同一老克隆独立测得 94 个 CRLF，检查只报 93）。现无扩展名的跟踪文件按文本判。
   - **老克隆要一次强制重检出**：`.gitattributes` 不回头改写已在磁盘上的文件，老克隆 `pull` 后
     磁盘仍是 CRLF 而 `git status` 干净（比对时 git 先归一）⇒ 只有第 4 项抓得到。
     解法 `git rm -r --cached . && git reset --hard`（实测 94 → 0、17 → 18 全绿），或删目录重 clone。
