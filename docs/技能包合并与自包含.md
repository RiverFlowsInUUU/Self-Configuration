# 技能包合并与自包含

> 📦 **决策记述（不随现状更新）**：本文回答的是「**当时为什么**这么合并」——
> 当时的取舍、被否掉的方案、以及合并后刻意保留的差异。**当前状态以各专项文档与 `CHANGELOG` 为准。**

> 本仓库是**独立仓库**：仓内每一条默认执行的检查都只看本仓库的文件，
> 不需要、也不依赖任何其他仓库在旁边。这篇文档记录"独立"是怎么来的，以及当时立的规则。

## 0 · 一句话结论

本仓的 `skill/SKILL.md` 是把两份**各服务于单一内核**的技能包合成一份双分支入口的结果。
合成是一次性动作，**生成脚本不进仓、已删除**——因为跑它就必须要求两个源仓的克隆同时在场，
与"独立"直接冲突。改写规则完整记录在下面，任何人不用那两个仓就能读懂这份 SKILL.md 为什么长这样。

## 1 · 合成时做的六件事

| # | 动作 | 具体规则 | 为什么必须这样做 |
|:-:|:-----|:---------|:---------------|
| ① | 换行归一化 | 读入后先把 `\r\n` 全部换成 `\n` | Windows 上 `core.autocrlf=true`，工作区 checkout 出来是 CRLF；而剥头部的正则按 `\n` 写——不归一化就**匹配不上**，源技能包的 YAML 头会整段留在正文里，合并后变成压在分支开头的假头 |
| ② | 剥 YAML 头 | `^---\n[\s\S]*?\n---\n+` 整段删除，合并版统一给一个新头（`name` / `description` / `agent_created`） | 一份文件只能有一个头。新头的触发词是两侧原触发词的**并集**，去重后按"用户会怎么说"排序 |
| ③ | 标题降一级 | 每行 `#{1,5} 空格` 前加一个 `#`——**但跳过围栏代码块内部**（遇到 ``` 或 ~~~ 翻转开关，开关打开期间的行一律不动） | 两侧各有一份完整文档，合并后要挂在 `# 配置防 DNS 泄露 · Surge / Egern 双内核` 之下。**不跳过代码块就是破坏模板**：YAML / conf 示例里 `# 注释` 开头的行会被当成标题，加出一个 `## 注释` |
| ④ | 路径加内核命名空间 | `reference/<名>.md` → `reference/<内核>/<名>.md`；`scripts/<名>.py` → `scripts/<内核>/<名>.py`；`profiles/<文件>.conf\|.yaml` → `<内核>/profiles/<文件>.conf\|.yaml`；通配写法 `` `profiles/*.conf` `` 同步改 | 两侧原有**同名文件**（`checker.md`、`pitfalls.md`、`audit_*.py`）。不加命名空间，合并后一半链接指向不存在的文件、另一半指向错的内核 |
| ⑤ | 分支标题落名 | 各自正文里第一个 `## ` 标题改写成 `## 分支 A · Surge 配置防 DNS 泄露` / `## 分支 B · Egern 配置防 DNS 泄露` | 前置章节的"内核判定"表格里有指向这两个锚点的跳转链接，锚点必须逐字对得上 |
| ⑥ | 拼接 | 新头 + Surge 分支 + `\n---\n\n` + Egern 分支 | 顺序固定为 Surge 在前，与文件名的字母序无关，只与"哪侧先写"的历史一致 |

**正文忠实度**：除 ② ③ ④ ⑤ 这类纯机械改写与下面第 2 节的两处登记修订之外，
两侧正文**逐字保留**，代码块逐字一致。本仓不声称"与任何源仓完全一致"，只承诺这一条。

## 2 · 仅有的两处刻意正文修订

源仓不改，只在合并版生效；两条都在 [`跨内核差异对照.md`](跨内核差异对照.md) §8 登记过。

| # | 位置 | 改动 | 原因 |
|:-:|:-----|:-----|:-----|
| 1 | Surge 分支「官方文档」小节 | 原来 4 条 `<https://manual.nssurge.com/policy/*.html>` 链接，换成 6 条：`/dns/dns-server.html`、`/dns/encrypted-dns.html`、`/dns/advanced.html`、`/rules/overview.html`、`/policy-groups/overview.html` · `parameters.html`、`/policies/overview.html` · `parameters.html` | Surge 手册改版，把旧的 `/policy/` 一层拆成 `/dns/` `/rules/` `/policy-groups/` `/policies/`，原 4 条链接现在全 404。新指向按**分支正文实际讲到的键**对应 |
| 2 | Egern 分支的社区参考实现 | `https://repcz.github.io/Egern` → `https://doc.repcz.link/egern/`（正文保留一句"原地址已迁至此"） | 该参考实现**搬家**，旧址现 404。⚠️ 判定过程差点出错：Windows 上 Schannel 的证书吊销检查离线时 curl 会返回 `000`，看着像"站点下线"实为假阴性——搬家是复核后确认的 |

两条都写成"**全文恰好命中 1 处**才替换，命中数不等于 1 就直接抛错"，
不接受"没找到就跳过"——那正是漏改还能全绿的典型姿势。

## 4 · "完全独立"这条纪律的具体含义

- 仓内**任何默认路径**都不指向两个前身仓库。需要外部参照时只指向**内核官方文档**
  （`manual.nssurge.com` / `doc.repcz.link`）；唯一的第三方引用是社区规则集与图标来源，
  那属于用社区公共资源，见 [`规则集与来源.md`](规则集与来源.md)。
- 检查项一律以本仓文件为输入：`bash skill/tests/all.sh` 跑的是两内核回归 + 全仓 markdown 链接与锚点
  + 两版形态去注释对拍（[`../skill/tests/check_min_pair.py`](../skill/tests/check_min_pair.py)）
  + 换设备可移植性（[`../skill/tests/check_portability.py`](../skill/tests/check_portability.py)），
  **没有任何一项需要外部仓库在场**。
- 字节层也不靠设备：仓根 [`.gitattributes`](../.gitattributes) 把检出钉成 `eol=lf`，
  覆盖 Windows 系统级 `core.autocrlf=true` ⇒ 同一个 commit 在任何机器上落盘字节相同，
  磁盘 = 提交 = 线上 raw 三处逐字一致。口径见 [`注意事项.md`](注意事项.md) 的「换设备 / 双端一致」。
- 因此本仓**不存在**"与源仓逐字节对账"这类检查，也不承诺源仓状态。合并工程的一次性验收已经完成，
  其结论落在本文档与 §8。
- 反过来说：本仓的 `SKILL.md`、profile、脚本都是**独立演进的正文**，后续所有人工修订都以它为准。
  按第 1 节的规则"重新生成一遍"会覆盖掉这些后续修订——**不要那么做**。

## 5 · 规则固化而非脚本化的理由

留脚本的好处是能重跑；重跑的前提是两个源仓还在——这正是本仓刻意切断的依赖。
而且建仓之后 SKILL.md 已在仓内被人工修订过（参数同步、版本升号、文案校正），
脚本生成的结果与现仓**不再等价**，留着它只会给下一个改动者一个错误的"真相源"。

所以取舍是：**规则进文档，脚本删除**。要复查当初的合并是否忠实，用的不是重跑生成器，
而是本仓自己就能跑的那几项（第 4 节末），加上第 2 节两处修订的逐字对照。
