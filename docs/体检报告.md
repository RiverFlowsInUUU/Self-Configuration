- `docs/注意事项.md` 通用表：「🔄 规则集刷新必须显式 | **全部远程规则集**带 24 小时刷新」；

**刷新参数没有任何留痕的豁免** ⇒ 不是明知故犯。另外全仓 13 个脚本里 `grep update_interval` 命中 0 个脚本
（只在 `skill/reference/*/{public-repo,hardening-template,ruleset-weight}.md` 的正文里提过），
**这一条根本不在审计覆盖范围内** ⇒ 属于「脚本全绿、配置仍有洞」的那类漏判面。

> ⚠️ **本报告初稿的因果是错的，已更正**：初稿写「不显式写 `update-interval`，规则集就会停在首次下载的版本」。
> Surge 手册对 `RULE-SET` 写明 `Default: 86400 (24 hours). A negative value disables auto-updating.`
> ⇒ **漏写不会停止刷新**，只是周期在文件里不可见、且与 Egern 侧不同构。真正**未文档化缺省值**的是
> Egern 侧（官方 `rules` 页只在示例里出现 `update_interval: 86400`，字段节只写 `no_resolve`）。
> 唯一会**真的**让规则集停在旧版的写法是**非正值**，全仓当前 0 处。
> 严重度据此从「配置失效级」下调为「可见性 + 同构性」，但**补参数这件事仍然值得做**：
> 一周是刻意的口径统一，且显式写出后 `--strict` 才守得住。

**实际影响**：`direct.txt`（11 万条，仓内称「国内直连主承重墙」）与两条广告清单若不刷新，
新收录域名会长期命不中——国内流量误走代理、新广告域名漏拦。Egern 懒人版尤其严重：它 6 条全不带。
另有一处**跨内核不一致**：`AI.list` 在 Surge 懒人版带 `update-interval=86400`，在 Egern 懒人版不带，
而 `docs/规则集与来源.md` §1 开头那句「两侧都必须显式写」正是针对这一整批共用规则集（含 `AI.list`）。

**解决方案（建议 A + C 一起做）**：

- **A 补齐配置**：给上述 32 处规则行补上 `"update-interval=86400"`（Surge，注意要作为最后一个参数、带引号）
  / `update_interval: 86400`（Egern）。改带注释版后逐字同步 `.min`。历史版本 `routing_v1 ~ v2.3`
  同样缺（0/21），但它们是刻意留档的历代版本，**建议不动**，只在 A 里写清「v2.4 起才补上」。
- **B 或改口径**：若刻意不想给广告清单/白名单加刷新（无技术理由支持这种选择），那就把三处文档
  从「全部 / 两侧都必须显式写」改成「分流版 v3 全覆盖，懒人版待补」，并给每处补 `# audit-waive:` 留痕。
- **C 补审计项**：在 `check_surge_dns.py` 与 `check_egern_dns.py` 各加一条判据
  「远程规则集条目必须带 24 小时刷新参数，缺失即 finding」，并接进 `run.sh` 的阶段 2 / 阶段 1，
  让它从此可回归。这条与仓内既有纪律一致（判据写在 profile 里、豁免用 `audit-waive`、脚本只报不改）。

## 八、🆕 P11 · 同一份 commit 在不同设备上落盘成不同字节 —— 高 · **已修**

**症状**：把"换个设备还能同样干活"当成已达成时，实际漏了行尾这一层。
`git config --system core.autocrlf` = `true`（Windows 版 Git 安装器写的系统级配置），
效果是 checkout 时把 LF 换成 CRLF ⇒ 同一个 commit 在 Windows 上落盘 **88 个 CRLF 文本文件**，
在 Linux / macOS 上落盘 LF。提交内 blob 本身是干净的（128 个跟踪文件里只有 26 个 png 含 CR 字节，
那是二进制的本征），坏的是**磁盘字节随设备变化**这一件事。

**为什么这是高优先级**：它同时打断三件本仓承诺的事——

1. 「线上线下逐字一致」在磁盘上无法验证（`raw.githubusercontent.com` 给 LF，本机工作树给 CRLF）；
2. 按 `\n` 写的正则在另一台机器上可能失配。**这不是假想**：本项目历史上真咬过一次，
   装配脚本剥 YAML 头的正则按 LF 写，在 CRLF 工作区上失配，源技能包的头部整段漏进正文（见 P4）；
3. 使用者的编辑习惯会反噬：Windows 编辑器保存成 CRLF，`git add` 时被规范化 ⇒ "改了没差异"，
   或者反过来把整份文件的行尾全改掉，diff 一片红。

**修法**（一次到位，不需要任何人改自己机器的 git 配置）：

| 步 | 内容 | 实测 |
|:--:|:-----|:-----|
| 1 | 仓根新增 `.gitattributes`：`* text=auto eol=lf` + 二进制资产标 `binary` + 常见文本类型显式列全 | `eol=lf` 优先级高于 `core.autocrlf`；本仓 `.bat` / `.cmd` / `.ps1` 数量为 0，故可取全 LF |
| 2 | `git add --renormalize .` | **索引零变化** ⇒ 反证提交内 blob 本来就是 LF，退役的是检出行为、不是重排历史 |
| 3 | 删净跟踪文件后重新检出 | **128 / 128 个文件磁盘字节 = 提交内 blob 字节**；工作树 CRLF 文件数 88 → **0**；`git status` 干净 |
| 4 | 固化成判据 `skill/tests/check_portability.py`（纯标准库，`all.sh` 第 4 项） | 报的是**固定 18 条规则**（行尾 / BOM / 零字节 / shebang / NFC / 非法字符 / 保留设备名 / 首尾空格与尾点 / 大小写折叠冲突 / 机器路径纯 ASCII / 长度 / 单机残留 / 符号链接与 submodule / `.gitignore` 兜底），**不随文件数增长** |
| 5 | 反例实测（怕它变成"永远全绿"的摆设） | 塞一个 CRLF 文件 → `E2` 红；把中文命名放进 `skill/` → `N6` 红（同名的放 `docs/` 不红，口径正确）；改掉 `.gitattributes` 那一行 → `E1` 红；三种都 `exit 1` 并点名文件 |
| 6 | 命名实测（128 条路径） | 全部 NFC、无非法字符、无保留设备名、大小写折叠零冲突、最长相对路径 **49 字符**、被跟踪的单机残留 0。中文文件名能正常上传 GitHub，本仓纪律是只在人读的 `docs/` 下用，机器消费的路径纯 ASCII |

**顺带**：`all.sh` 末尾加一行双端对账 `未提交 N · 落后 N · 未推送 N`（三个数全 0 才算同步；
没有上游时如实写「未配置」，不静默）。三项既有读数不变（Surge 19 离线 / Egern 46 / 形态对拍 12）。
